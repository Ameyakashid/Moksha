# Dead Cells shield/parry evidence → MOKSHA PC contract

Read-only research, 2026-10-04. Target: ordinary Beheaded shield use and coupled weapon permissions; an independently authored Godot implementation. No NPCs, level expansion, original game assets, game execution, or copied implementation. MOKSHA `combat_pc/player.gd` was inspected at SHA-256 `4aa4132650037e5c975de27547ef06c6dd1e95a3c7384d9744524de048a8760a`; no implementation files were edited.

**Result:** the pinned source establishes separate shield hold/parry hooks, a real cancellation gate, and an outgoing counterattack dispatch. Official developer notes establish the qualitative guard/parry tradeoff and important exceptions. The actual input-to-parry lifecycle, directional geometry, recovery, damage math, and movement/cancel matrix remain missing. None of the numbers for the new MOKSHA shield should be described as recovered v35 parity.

Companion: [SHIELD_PARRY_SOURCE_FACTS.json](SHIELD_PARRY_SOURCE_FACTS.json) records the 37 fetched source-file blob hashes, 11 bounded facts, and unresolved contracts. It contains no original implementation.

Existing combat and movement audits were read first. The complete saved tree has 1,888 entries; targeted files were fetched at this exact commit.
- **BODY** = nonempty decompiled body, still not verified runtime equivalence. **CALL** = actual dispatch whose callee is absent. **DECL** = fields/signatures/stubs, not recovered behavior. **PRIMARY** = official developer statements with historical version. **MOKSHA** = original project choice.
- GitHub code search found only declarations/overrides for `onShieldHolding`, only the missing directional predicate for `isFrontBlockingAttack`, and no implemented caller of `BaseShield.shieldCounterAttack`. It also found a separate, empty `BubbleShieldPower.shieldCounterAttack`; that is not a recovered caller or ordinary shield lifecycle. Search results are a cross-check, not proof of all possible dynamic calls.
- No controlled, version-identified official gameplay clip was measured in this pass. Searches found developer prose and general promotional footage, not evidence sufficient to settle input edges or frame boundaries. There are **no MEASURE values** here. Community wiki/forum timing numbers were excluded from the contract. The former movement audit's unplayed/buffering GDC video is not a shield measurement.
- Analysis only: the repository's licensing conflict described in the movement audit does not establish permission to transplant the original game code.

## Historical primary constraints worth preserving

These are developer-authored patch statements, not a complete current executable specification. Site numbering is retained (for example `/12` includes the 1.2 era).

- [12.3, 2019-02-26][p12]: fixed shield control-lock bypass through dodge while holding, with an Assault Shield exception; ParryShield exploits are mentioned separately. [12.4, 2019-03-05][p12]: total shield-use control lock should be consistent across shields. **Do not let roll cancellation simply delete an incurred lock. This is not evidence of a blanket roll ban while holding.** The text does not identify that lock as miss-only, define its interval, or specify which controls remain usable.
- [29, 2022][p29]: optional easier parry timing and shield-toggle input exist. [AssistModeData 5, 26][assist] defaults `easyParry` to false; its consumer is missing. Reference measurements must record accessibility/input settings.
- [34, 2023][p34]: Alucard's Shield received a different parry window and combo critical behavior. [35][p35]: legendary Assault Shield charges its dash while held and releases it afterward. [DashShield 35–38][dash] actually calls the base parry-start method when a charged dash is released. **This concrete subclass is not evidence that every shield opens a new parry on release.**

## Recommended original Godot interfaces

All interfaces and lifecycle choices below are **MOKSHA**, grounded in the boundaries above rather than copied Haxe.

1. **ShieldController / ShieldProfile:** own raise/parry/hold/recovery, attempt serial, held/released edges, input rearming, accepted-hit IDs and outcome hooks. Profile owns holdability, phase timings, guard absorption, separate successful/missed recovery, ground/air/turn permissions and impact tuning. Keep explicit `parry_window_from`/`until`; half-open tick boundaries are a MOKSHA implementation convention. Do not make animation completion the only simulation clock.
2. **Action arbitration:** compose locomotion capabilities, current melee permissions, shield permissions and external restrictions. Add shield entry/cancellation to the existing permission APIs; do not overwrite an external `can_move=false` or allow an unrelated action to reset post-use locks. Admission and cancellation should be transactional: reject without partially cancelling melee/traversal. Resolve simultaneous attack/shield/roll once per tick with a documented MOKSHA priority.
3. **IncomingAttack / DefenseResult:** input carries stable attack/contact ID, source, carrier, contact/origin/approach geometry, damage/impulse, attack kind, and independent block/parry/reflect/roll eligibility. Return an explicit outcome such as evaded, parried, guarded, hit or duplicate, plus residual damage and redirect/counter request. Never reinterpret `receive_hit`'s existing Boolean as sufficient to describe all of those outcomes.
4. **Counter/Reflect adapters:** melee counter request targets its source through the normal attack-result pipeline; projectile adapter reports whether redirect was accepted; the incoming parry stays successful if later retaliation fails. Record separate defense-success and counter-hit-success events. If the fixture has no counter receiver, report that honestly instead of fabricating damage.
5. **Feedback and integration:** emit one contact/noise/hitpause event per accepted result. Route impulses through the established physics/contact layer, retain wall occlusion, and leave regular locomotion collision intact. During actor-local hitpause, preserve the existing input-edge capture and safe carrier transport. Whether shield clocks pause is explicit MOKSHA policy; freeze them consistently with the PC's attack clocks unless a later measured reason changes it.

The inspected PC already exposes `set_weapon_permissions`, `can_interrupt_with`, `_weapon_allows_cancel`, `receive_hit`, `apply_hitpause`, `strike_snapshot`, `confirm_strike` and `noise_requested`. Implement against those seams or deliberately replace them with a documented adapter. Keep the player script's accumulated traversal guards intact.

## Minimal playable policy and explicit gaps

For this milestone, ship one ordinary holdable shield plus passive attack fixtures. A maintainable **authored** policy is: a fresh accepted press starts one attempt; an active parry interval is finite; sustained input becomes guard; a miss ends in visible recovery; release ends guard; success permits a documented next attempt; holding alone cannot rearm repeated windows. Turning, horizontal reduction, air continuation, jump/roll/attack cancellation and success recovery must each be profile choices and tests. These choices are **not** a recovered v35 state machine. No inspected primary wording or nonempty body establishes immediate successful-parry rearming/cooldown reset; select and label that behavior independently of the recovered counter callback.

Required tuning ledger entries: press/raise latency, parry start/end, hold-entry delay, post-miss and post-success lock, release/rearm behavior, buffer lifetime, ground speed, air drag/gravity policy, phase turn permissions, all cancel gates, guard absorption, damage/critical math, counter impulse/stun, reflection speed/direction, shield contact geometry, hitpause and noise magnitude. Label every value authored MOKSHA tuning until independently evidenced.

MOKSHA's own [source spec](../../docs/MOKSHA-source.md) requires fast side-on combat, hit nanopauses, meaningful sounds, and physical people/objects (lines 15–20, 54, 259, 273–277). Lines 117–119 describe eventual agility-versus-strength parry-window/damage tradeoffs. Preserve profile extensibility for those later lenses; do not add senses/lore or build progression in this PC-only step.

## Concrete passive-fixture acceptance tests

1. **Timing edges:** hit before opening, first open tick, last open tick and first closed tick; short tap, long hold, release and quick re-press. Each accepted attempt has exactly one serial; a held button does not silently renew its parry window. Show the selected policy in telemetry.
2. **Outcome split:** the same frontal melee contact produces normal hurt when idle, partial damage in guard and zero incoming damage in active parry. A parry against an invulnerable/absent counter receiver records defense success without counter-hit success. Guard residual damage must not accidentally run both guarded and full-damage paths.
3. **Geometry:** mirrored left/right, behind, directly above/below, equal-X overlap, diagonal approach and a projectile whose distant owner is on the opposite side from its carrier. Explicitly record authored accept/reject geometry. Solid-wall-occluded contacts cause neither hurt nor parry/noise/counter effects.
4. **Attack categories:** blockable-only, parryable-but-not-reflectable, reflectable projectile, grenade adapter and entirely unblockable/avoidable fixtures. The non-parryable flag must survive correct timing and facing. A reflected projectile changes its intended owner/target behavior once and cannot also damage the player from the old contact.
5. **Repeats:** duplicate callback for one attack ID, sustained area overlap, simultaneous distinct attacks, two closely spaced hits and fresh next attempt after success/miss. No duplicated counter, reflection, impulse, audio, noise or reward; deduplication must not suppress a genuinely new attack.
6. **Permissions:** attempt shield from each melee phase, and move/turn/jump/roll/attack/drop/dive/climb/wall from each shield phase. Test both allowed and denied external permissions. Shield→roll cannot erase unexpired control lock; nonholdable-profile cancellation respects its explicit gate. Rejected admission leaves the previous action and input buffers coherent.
7. **Air/landing/hitpause:** rising, falling, soft/hard landing, moving carrier, wall/ledge loss and hitpause with press/release/reverse input. Preserve air-jump budget, fall-risk history, collision clearance and carrier safety. No extra jump, hover, roll protection or stale shield after damage/reset.
8. **Feedback:** guard, parry, reflect, failed counter and miss have distinguishable original poses/events. One effective impact produces the intended nanopause and noise event; failed/occluded/duplicate contacts produce no false success. Existing melee, props and traversal regression checks still pass.

These tests verify the declared MOKSHA contract. Passing them is not evidence of exact Dead Cells timing or invisible invulnerability parity.
